# Звіт з практичного заняття №1

Тема: Системи числення і машинне представлення даних
Варіант: 7 (N = 105, F = 0.35, A = -50, B = -60, C = -64.25)
Інструмент: Python 3, редактор Visual Studio Code

## 1. Переведення N у двійкову, вісімкову, шістнадцяткову системи; F у двійкову

### N = 105 (ціле, переведення послідовним діленням на основу)

Двійкова (ділення на 2, остачі знизу вгору):

```
105 / 2 = 52  остача 1
52  / 2 = 26  остача 0
26  / 2 = 13  остача 0
13  / 2 = 6   остача 1
6   / 2 = 3   остача 0
3   / 2 = 1   остача 1
1   / 2 = 0   остача 1
```
Результат (знизу вгору): 105(10) = 1101001(2)

Вісімкова (ділення на 8):
```
105 / 8 = 13  остача 1
13  / 8 = 1   остача 5
1   / 8 = 0   остача 1
```
Результат: 105(10) = 151(8)

Шістнадцяткова (ділення на 16):
```
105 / 16 = 6  остача 9
6   / 16 = 0  остача 6
```
Результат: 105(10) = 69(16)

### F = 0.35 (дріб, переведення послідовним множенням на 2, 6 розрядів)

```
0.35 * 2 = 0.70  -> 0
0.70 * 2 = 1.40  -> 1
0.40 * 2 = 0.80  -> 0
0.80 * 2 = 1.60  -> 1
0.60 * 2 = 1.20  -> 1
0.20 * 2 = 0.40  -> 0
```
Результат: 0.35(10) ≈ 0.010110(2)

Похибка: точне двійкове представлення 0.35 нескінченне (0.0101100110011...),
тому обрізання до 6 розрядів дає наближене значення 0.34375 замість 0.35.

## 3. Додатковий код, додавання A і B, переповнення

A = -50, B = -60, розрядність - 8 біт.

Переведення в додатковий код:
- 50(10) = 00110010(2); інверсія: 11001101; +1: **11001110** = -50 у дод. коді
- 60(10) = 00111100(2); інверсія: 11000011; +1: **11000100** = -60 у дод. коді

Додавання в стовпчик:

```
  11001110   (-50)
+ 11000100   (-60)
-----------
  10010010
```

Перенесення зі старшого (сьомого) розряду за межі 8 біт відкидається.

Переведення суми 10010010 назад у десяткову: старший біт 1 -> число
від'ємне; інверсія 01101101, +1 = 01101110(2) = 110(10), отже сума = **-110**.

Перевірка: -50 + (-60) = -110 - збігається.

Визначення переповнення без переведення в десяткову: переповнення виникає,
коли перенесення в знаковий (7-й) розряд не дорівнює перенесенню з
знакового розряду. У даному випадку перенесення в 7-й розряд = 1 і
перенесення з 7-го розряду = 1, вони рівні, тому **переповнення немає**.
Це логічно, оскільки -110 входить у діапазон 8-бітного додаткового коду
(-128...127).

Вивід програми:

```
A = -50 -> 11001110
B = -60 -> 11000100
Сума (8 біт):     10010010
Сума в десятковій: -110
Переповнення:      False
```

Висновок: ручний розрахунок і вивід програми збігаються.

## 4. Розбір C за форматом IEEE 754 single

C = -64.25

Знак: число від'ємне -> знаковий біт = 1

Переведення модуля в двійкову: 64 = 1000000(2), 0.25 = 0.01(2), отже
64.25(10) = 1000000.01(2)

Нормалізація до вигляду 1.xxx * 2^p: 1000000.01 = 1.00000001 * 2^6

Порядок зі зміщенням 127: 6 + 127 = 133(10) = 10000101(2)

Мантиса (23 біти, без прихованої одиниці): 00000001 доповнене нулями до
23 розрядів -> 00000001000000000000000

Повний 32-бітний запис (знак + порядок + мантиса):

```
1 10000101 00000001000000000000000
```

Відновлення значення з бітів: мантиса дає 1 + 2^-8 = 1.00390625;
1.00390625 * 2^6 = 64.25; зі знаком -> **-64.25**, що збігається з C.

Вивід програми (біти отримані через `struct.pack('>f', C)`):

```
32 біти:   11000010100000001000000000000000
Знак:      1
Порядок:   10000101 = 133 (зі зміщенням), незміщений = 6
Мантиса:   00000001000000000000000
Відновлене значення: -64.25
```

Висновок: ручний розбір і побітовий вивід програми повністю збігаються,
відновлене значення дорівнює вихідному C.

## 5. Похибка суми дробів

Обчислення в програмі:

```
0.1 + 0.2 = 0.30000000000000004
0.1 + 0.2 == 0.3: False
```

Причина розбіжності: числа 0.1, 0.2 і 0.3 не мають точного скінченного
представлення у двійковій системі (це нескінченні періодичні двійкові
дроби), тому кожне з них зберігається в пам'яті з округленням до
найближчого представленого числа формату double. Похибки округлення
0.1 і 0.2 при додаванні не компенсують одна одну і не дають рівно те
саме округлене значення, що зберігається для 0.3, тому пряме порівняння
через `==` дає False.
